# What the bots remember

On a new level the standard native and JKWeb seats can build a route graph from the level geometry and visible pickups. Traversal checks decide which edges a bot can attempt. After the engine reports that a bot arrived or stalled on a directed edge, the launcher updates a small set of route-cost weights for that seat. A new match loads the latest weights. A graph with unfamiliar sector numbers can still use what the bot learned about distance, elevation change, connection type, water, items and connectivity. The native client can also remember costs for particular edges on a recognized level.

The weights live in `$XDG_STATE_HOME/adjoin-arena/navigation`, defaulting to `~/.local/state/adjoin-arena/navigation`. Set `ADJOIN_NAV_MEMORY` to a persistent directory writable by the launcher to keep the state across test directories or container restarts. Set it to `off` for a clean baseline. Each engine build and seat has its own store with separate NF guns, NF sabers, FF guns and FF sabers profiles. Keep this directory when retiring test copies. A change to the engine's identity starts a new profile. Browser seats joining an existing room need a verified supported Force rank before saving outcomes to a rules profile.

A standalone native match with fixed rules can use its seat's learned weights on the first visit to a new map. When a manager or an external behavior file can change the rules during play, the native supervisor assigns each outcome to the rules the engine reported at that point. The current native binary loads a cross-map prior once per launch. In these live-editable sessions it uses map-specific recall and trains the cross-map banks for a subsequent fixed-rules match. Browser seats open their banks independently and report per-seat learning availability in host status. [Native settings](../bots/README.md) · [Browser host](../web_bots/README.md)

In a fresh NF guns series, Darth Lilitari recorded 21 route outcomes on her first JHS visit and another 19 on her return. On that return the engine reported using the saved weights in route scoring. In her first game on Bespin, it used the weights learned on JHS and collected 29 more outcomes. Red had 19 updates over the series. These observations establish persistence and transfer. The series did not measure a change in win rate. [Three-room results](../qa/persistent-navigation.json)

Two 35-second native Nar Shaddaa games used the same NF guns profiles. Jan and Boba accumulated 16 and 25 observations in the first game. Both engines reported the matching saved weight digests during route scoring on the return visit. Jan then added 33 observations and Boba added three. A third match reopened the same persistent store from a different Ubuntu installation. The packaged engine used Jan’s 49-step prior and Boba’s 28-step prior during route scoring. They added four and eleven outcomes, respectively. All three games used the original-clock binary. [Native repeat receipt](../qa/persistent-navigation.json)
